# A2 failure paths
## Mission
Find added code that mishandles failure: swallowed errors, wrong error type at a boundary, missing timeout, retry or rollback, leaked resources, or an error path with no log or metric.
## Axes
`errors`, `resources`, `observability` (research-axes.md §2a axes 3 and 5, §2c axis 17). S21: 92% of catastrophic failures come from mishandled non-fatal errors.
## Read these language references
`idioms.md` rows Errors, Resources; `severity.md` (appended below).
## Checklist
1. Swallowed errors: empty `except`/`catch`, `except Exception: pass`, `_ = err`, `.ok()`/`let _ =` on a fallible call, a returned error ignored, a promise not awaited and not caught.
2. Lost errors: an inner-scope `err :=` shadowing so the outer function returns nil; error replaced without the cause (`raise X` without `from`, `%v` instead of `%w`).
3. Wrong error type or contract at a boundary: a panic or `unwrap()` on fallible I/O in library code, an error type callers cannot match, a sentinel changed.
4. Missing timeout on network or subprocess calls; retry without backoff or on a non-idempotent call; partial failure with no rollback.
5. Leaks: file, socket, connection, lock, goroutine, task, timer opened on a path where an early return or error skips the close; `defer` in a loop; unbounded queue or buffer (CWE-770).
6. New failure mode with no log, metric or returned error, so operators cannot see it.
7. Read the callers before claiming impact: a caller may handle the error (grep the function name).
## Do not report
- Linter-caught cases (e.g. errcheck, `B110`, `clippy::let_underscore_must_use`) if the linter is enabled.
- Deliberate ignores with a comment that gives a reason.
- Wrong results on success paths (A1a), security (A3), races (A4).
- Lines this change did not add.
## Proof plan hints
- E4: a fault-injection test: make the dependency raise or return an error or timeout, assert the documented behaviour (error returned, rollback done).
- E3: a snippet showing the error disappears (e.g. function returns nil after the inner error).
- E5 for leaks: `python -X dev` ResourceWarning, goleak, fd count before and after.

# A4 concurrency
## Mission
Find concurrency defects the added code introduces: data races, deadlocks, leaked goroutines or tasks, a lock held across await, Send/Sync misuse, or broken cancellation.
## Axes
`concurrency` only (research-axes.md §2a axis 4). S22: Go blocking bugs are mostly message passing; S23: Rust blocking bugs are all in safe code.
## Read these language references
`idioms.md` rows Concurrency; `cookbook.md` rows Sanitizer (appended below).
## Checklist
1. Shared mutable state (maps, slices, dicts, counters, globals, struct fields) written from more than one goroutine, thread or task without a lock, atomic or channel.
2. Lock order: two locks taken in different orders on different paths; a lock not released on an error path; re-entrant locking of a non-reentrant lock.
3. Async: a `std::sync::Mutex` / `threading.Lock` guard held across `.await`/`await`; blocking calls (`time.sleep`, sync I/O) inside `async` code; `asyncio.create_task` / spawned task with no kept reference or join; `forEach(async …)` whose caller assumes completion.
4. Channels: never closed, never read, send on a closed channel, unbuffered send with no receiver; `WaitGroup.Add` inside the goroutine.
5. Cancellation: context or token not passed or not checked; task not cancelled on error; timer or interval not cleared.
6. Rust: `unsafe impl Send/Sync` without a justification; `Rc`/`RefCell` crossing threads; `Arc<Mutex<…>>` held across await.
7. Show the interleaving: name the two concurrent paths with `path:line` and the order of events that breaks.
8. "The detector found nothing" is not evidence the code is clean (S22, S24, S27).
## Do not report
- Code that runs on one thread or task only (read the callers to confirm).
- Races on data that is immutable after construction.
- Generic "consider a lock" advice without a concrete interleaving.
- Lines this change did not add.
## Proof plan hints
- E5: `go test -race`, Miri, TSan, `python -X dev` with asyncio debug (cookbook Sanitizer row). Report the race output verbatim.
- E4: a stress test (`-count=100`, many tasks) asserting the invariant.

# A5 contracts, data and portability
## Mission
Find added changes that break a public contract, a wire or storage format, a migration's safety, or the supported platforms and minimum versions.
## Axes
`api`, `data`, `portability` (research-axes.md §2a axes 9–10, §2c axis 21). S24: one third of releases break, minor releases included. S25: schema bugs are 22.5% of DB-access bugs.
## Read these language references
`tools.md`; `cookbook.md` rows API break (appended below).
## Checklist
1. Public API: a removed, renamed or re-typed exported symbol; a changed default; changed error semantics; a new required parameter. Decide "public" by the language rule (exported, `pub`, `export`, no leading `_`) and by whether it is re-exported.
2. Callers not migrated: grep every changed symbol across the repo; read each caller and check it matches the new signature and semantics.
3. Wire and schema: JSON or proto field renamed or renumbered, enum value removed, API response shape changed, CLI flag or env var renamed.
4. Migrations: not reversible, locking DDL on a big table, `NOT NULL` without a default or backfill, code that needs the new schema deployed before the migration, missing transaction.
5. Portability: platform-specific paths or syscalls, a language feature newer than the declared minimum (`requires-python`, `go` directive, `rust-version`, `engines`, TS `target`), endianness, conditional compilation that drops a platform.
6. Semver: a breaking change shipped without a major version bump when the repo versions its API.
## Do not report
- Changes to private or internal symbols with all callers migrated.
- Intended breaks that the commit message or changelog states, with callers migrated.
- Supply-chain issues in dependencies (A5b) and config or deploy order (A8).
- Lines this change did not add.
## Proof plan hints
- E1: an API-break tool from `cookbook.md` (griffe check, apidiff, cargo semver-checks, api-extractor) or a type checker run showing a caller no longer compiles.
- E4: compile or run an old caller fixture against the new code.
- E9: apply the migration up and down on a fixture database.

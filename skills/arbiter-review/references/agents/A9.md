# A9 accessibility and i18n
## Mission
Find added UI code that fails basic WCAG checks or hard-codes user-facing strings in a project that localises them.
## Axes
`a11y` only (research-axes.md §2c axis 20). S30: 94.8% of pages fail WCAG; six error types make up 96% of errors.
## Read these language references
None.
## Checklist
1. Images without `alt` (decorative images need `alt=""`).
2. Form inputs without a label (`<label for>`, `aria-label`, `aria-labelledby`).
3. Empty buttons and links: icon-only controls with no accessible name.
4. Low contrast: hard-coded colour pairs in CSS or inline styles whose contrast ratio is below 4.5:1 for normal text. Compute the ratio; do not guess.
5. Missing `lang` on the `<html>` element of a new page or template.
6. Keyboard: click handlers on non-interactive elements (`div`, `span`) with no `role`, `tabIndex` and key handler; `outline: none` with no focus style; positive `tabIndex`.
7. i18n: hard-coded user-visible strings, dates or numbers formatted without the locale, only when the repo already uses an i18n library or message catalogue (grep for it and cite a precedent).
## Do not report
- Strings in tests, logs, error codes or developer-only screens.
- i18n gaps in a project with no i18n setup.
- Visual taste, layout, or ARIA you only think could be better.
- Lines this change did not add.
## Proof plan hints
- E1: a measured fact: the element line with no `alt`/label, the computed contrast ratio of the two colours, or an axe/pa11y/eslint-plugin-jsx-a11y rule hit if the repo has one.

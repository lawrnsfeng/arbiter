# A8 ops and config
## Mission
Find added config, deploy and observability changes that make a rollout unsafe: config without a default or validation, unwired flags, unsafe deploy order, secrets in config, or new failure modes nobody can see.
## Axes
`ops`, `observability`; `security` with `cwe: 798` for secrets in config (research-axes.md §2c axes 17–18). SRE: about 70% of outages come from changes to a live system (S18).
## Read these language references
None.
## Checklist
1. New config value or env var read (`os.environ[...]`, `os.Getenv`, `env::var`, `process.env`): is there a default or a clear start-up error when it is missing? Is the value validated (type, range)? A crash deep in a request on a missing value is a finding.
2. Feature flag or config key added but never read, or read under a different name than the one defined (grep both names).
3. Renamed env var, port, script or secret path that existing deploy files (Dockerfile, compose, helm, k8s, workflow, Makefile, `.env.example`) still use under the old name: a devex break (pstack thermo-nuclear-review).
4. Deploy order: code that requires a new schema, service or config to exist before it ships, with no fallback.
5. Secrets committed in config files, Dockerfiles, workflows or `.env` files (real-looking keys, not placeholders).
6. Dockerfile and CI: running as root when the repo does not elsewhere, `latest` tags where the repo pins, a removed health check.
7. A new failure mode (new external call, new error branch) with no log, metric or alert, so operators cannot detect it.
## Do not report
- Placeholder values in example files.
- Code behaviour bugs (A1a–A2), dependency changes (A5b).
- Style of YAML, Dockerfile or Makefile.
- Lines this change did not add.
## Proof plan hints
- E1: a measured fact: the env var name defined in one file and read under another (`grep -n`), a config schema validation or dry-run failure.
- E4: a test that starts the program without the new variable and asserts a clear error.
## Output
`{"findings": [...]}`; `axis` `ops` or `observability` (or `security` with `cwe`); `trigger` names the deploy or config state.
